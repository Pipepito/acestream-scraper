Corrections and newly discovered risk

  1. No manual Google Cast editor exists in current source. The earlier Connections mockup incorrectly offered one. It is corrected to point to actual remote-player setup; historical image 18 still records the old concept and is labelled accordingly. Normal home accounts/Cast never require browser pairing. VLC Android pairing is a real and separate workflow.
  2. Telegram has its own transport/header constraint. Do not copy normal private-HTTP account rules into authorization of the Telegram session.
  3. Bulk stream edit source mismatch — new, not live-reproduced. BulkOperations.tsx exposes category/country/language and loops per selected row. AcestreamChannels.tsx passes the complete selected ID list to the batch endpoint on each callback. AcestreamChannelUpdate declares none of those three fields; the endpoint uses its validated model_dump. This is strong source evidence for ineffective metadata edits and repeated batch requests, not a claim of observed installation corruption. See source finding F15. Keep TV-channel properties with their canonical owner; verify request count and result truthfulness in #315/#320.
  4. Machine values corrected during composition: guide strictness balanced; exclusion name_equals/stream_id_equals; W3U All/Favorites/Recent and save-only; event provider wosti_es, input schema_org, state postponed; full currently offered WARP modes; export offset-to-days_back conversion. These are design corrections, not application fixes.
  5. Separate save boundaries are visible. WARP mode/licence, individual scheduler intervals, PID/AppID and cleanup policy/anchors no longer appear as an atomic operation. Proposed staged saves still require review where source currently saves immediately.

The previous recording crash, contrast failures, phone clipping and unnamed guide sliders remain unresolved application findings. Performance slowdown remains unproven. No synthetic screenshot changes their status.
