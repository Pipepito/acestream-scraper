DESIGN REFERENCE / STATIC SNAPSHOT

Material Design 3 → ZZSTREAMS component audit

Reviewed 9 November 2026 against Google's official Material Design 3 catalogue, including its current Expressive button, menu and progress guidance. This is a component-coverage reference for the static design system, not an adoption of Google's brand or a production frontend implementation.

Interactive component library · Brand foundations

What was missing

The previous brand page demonstrated primary/secondary/destructive buttons, basic fields, badges, a confirmation dialog, filter buttons, loading skeletons, empty/error states and playback controls. Actual mockups already had navigation, tables and forms, but many primitives lacked a reusable visual/interaction contract or a live specimen. Selection controls, field variants, chips, menus, tabs, sheets, snackbars, tooltips and progress were the largest gaps.

Product-specific complements include breadcrumbs, pagination, accessible data tables, empty/retry outcomes and disclosures. They use the same tokens without claiming to be newly supplied Material 3 components.

What stays ours

  • Color: Signal Pitch cyan, ink/paper neutrals, original lime/coral composition accents and accessible semantic pairs. Light controls use dark teal for contrast.
  • Type: supplied Inter for reading/controls, Barlow Condensed for display.
  • Shape: existing 8px controls and 12px cards. Pills belong to search and switch tracks; a sheet gets a larger corner only where its layer needs distinction.
  • Density: four-point spacing, 48px target goal, readable 16px phone inputs.
  • Identity: new uppercase ZZSTREAMS PNG signature, retaining the supplied icon family, photographer attribution and the earlier SPORTZZ originals as provenance.
  • Motion: short feedback, no decorative morphing in administration, no carousel autoplay and no animated rotation when reduced motion is requested.

Behavioral decisions

  1. Switches act immediately. Saved or restart-dependent settings must not adopt switch semantics merely for appearance. Existing mockup forms are not rewritten.
  2. Tabs and navigation differ. Tabs reveal related local panels; destinations use links and aria-current. Selection never destroys unrelated drafts.
  3. Unknown work stays unknown. No percentage on indeterminate progress. The catalogue's advance button is visibly labelled a simulation.
  4. Undo remains available. The actionable snackbar does not time out. Errors persist beside the relevant field/action. No live region receives focus merely because its text changed.
  5. Native controls preserve access. Date/time interiors, select popups and range interaction remain platform-native. A branded custom calendar, analog clock, multi-thumb slider and gesture-driven dismissals are not implemented.
  6. Styles are shared, examples are isolated. Component CSS is in the shared system file, with no remote fonts, JavaScript framework or Material dependency. Existing mockup actions retain their own engine. No production application APIs, player ownership or saved settings are changed by this static extension.
