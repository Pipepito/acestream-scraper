# v2.2.0 release notes — draft

Target: `v2.2.0`, via [#207](https://github.com/Pipepito/acestream-scraper/pull/207).
Publication date is not yet scheduled. Development images use floating
`develop*` tags. This describes integrated work, not a published stable release.

## Integrated release scope

Snapshot: 2026-10-21, develop `bd5e184`, compared with main `7fe2a4c`.
Recheck with `git log --oneline origin/main..origin/develop` and the current PR.

- **Validation reliability (#243).** Bound each engine recovery separately, keep
  the dummy app alive while checking auxiliary startup failures, retry one reset
  on read-only browser API calls, and record cancelled reads separately from
  failed requests while retaining strict mutation/error checks.
- **HTTP/HLS streams and live broadcasters (#241, issues #234/#235).** Import
  ordinary HTTP/HLS playlist entries and their headers, verify bounded media
  samples without engine sessions, and publish direct URLs or signed manifest
  routes. Atresmedia, Mediaset, Telemadrid and 7 TV La Rioja source providers
  resolve expiring links at playback. Guarded reads, deadlines, cancellation,
  HLS keys/init segments, byte ranges and discontinuities are preserved. These
  providers need no user account; account-required channels are outside scope.
  Mixed HTTP/AceStream tuner failover remains separate work. See
  [HTTP streams](../../wiki/HTTP-Streams.md).
- **Guide setup (#205/#206/#215, issue #204).** XMLTV discovery in M3U, reviewed
  EPG matching and opt-in conservative automatic matching. Unknown imported
  guide IDs fall through to names while authoritative IDs and ambiguity guards
  remain intact.
- **Notifications (#228/#230/#231, issue #41).** Optional webhook/Gotify summaries
  cover scheduled/run-now jobs, manual scrapes and individual checks. Invalid
  webhook settings are rejected and malformed legacy settings can be recovered.
  Skips and playback probes stay quiet. Native Telegram configuration and
  continuous offline-transition alerts are not part of this feature.
- **Playback (#219–#223/#227/#240).** Configurable tuner startup budgets,
  25-second stall detection, bounded empty-start retries, exact session cleanup
  and safe disconnect linger. Kodi hints and optional per-source playlists
  retain filters and guide identity. Recent verified candidates precede stale
  and unknown alternatives, within the existing startup budgets.
- **Scheduling and database (#236–#239).** SQLite waits up to 30 seconds for a
  lock. Startup catch-up uses persisted history, grace periods and staggered
  launches. Stream checks prioritize unchecked/older streams fairly and pause
  between probes during app-owned viewing, with a ten-minute cumulative limit
  and truthful deferred-work/FIFO reporting.
- **Sources and catalogue (#211/#218/#225/#229/#242).** Preserve content-ID versus
  infohash identity and source catalogues on TV-assignment conflicts. Support
  ID search and canonical API URLs. Pinned fetches send Host first. ZeroNet
  handles zero:// URLs, missing-site bootstrap and bare links.json, preserving
  complete gateway URLs, custom ports and prefixes.
- **Runtime (#209/#215/#232/#244).** Respect FLASK_PORT; bundle Kubo 0.43.1;
  report the selected release version; distinguish optional-engine/disabled-WARP
  states from failures; share a cold storage scan across concurrent requests.
- **CI (#212 and follow-ups, #245).** Reuse dependency-keyed runners, retain
  useful cache with pressure-aware cleanup, and acquire the shared FIFO Docker
  lock before allocating an executor. Fork isolation and manual release guards
  remain in place.

## Upgrade notes

Back up persistent configuration/database before upgrading. Startup applies
Alembic revisions with the existing pre-upgrade backup/recovery procedures.
This cycle includes `20260928_1200` (channel ID kind) and `20261021_1200`
(HTTP stream URL/headers); it is not migration-free.

The six deprecated environment aliases remain supported, including .env,
canonical nonempty-value precedence and name-only warnings. Retirement (#155)
is deferred. Notifications and WARP remain opt-in. A failed dedicated checking
engine never falls back to playback. ARMv7 engine runtime remains experimental
pending physical hardware validation.
