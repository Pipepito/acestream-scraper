# v2.2.0 release notes — draft

Target: `v2.2.0`. This document describes release preparation, not a published
release. Development images continue using floating `develop*` tags.
The release PR is [#207](https://github.com/Pipepito/acestream-scraper/pull/207).

## Changes already integrated into develop

Snapshot: 2026-10-20, `e4e5639`, compared with main `7fe2a4c`.

- Guide discovery in exported M3U, reviewed EPG matching and opt-in automatic
  exact matching (#205, #206, #215; issue #204). Unknown imported guide IDs fall
  through to name matching while preserving original identities and assignments.
- Optional webhook/Gotify notifications for scheduled and run-now scraping and
  stream-status jobs (#228; issue #41).
- Configurable tuner startup budgets, a 25-second stall threshold, bounded retry
  for an empty first response, and corrected session ownership/cleanup (#219–#223,
  #227). Kodi media hints and optional per-source playlist entries preserve guide
  IDs and filters. The direct engine JSON-start timeout is a separate remaining
  question in #226.
- Scraping preserves the source catalogue when TV-channel association conflicts
  with an existing assignment (#225). Pinned source requests send Host first
  for upstream compatibility (#218).
- Channel imports retain content-ID versus infohash identity (#211). Acestream
  Channels search accepts IDs and uses canonical API URLs without 307 redirects
  (#229).
- Container startup honors `FLASK_PORT` (#209; issue #208); bundled Kubo is
  0.43.1 (#215; issue #214).
- Dependency-keyed CI runners, pressure-aware cache retention and validated
  maintainer-owned PR image builds (#212 and subsequent corrections).

## Follow-up batches

These changes are delivered as independent PRs into develop. Confirm each merge
before including it in the final release:

1. Webhook syntax validation, preserving valid saved URLs after rejected updates,
   plus UI recovery for malformed values saved by older versions.
2. One summary notification for each manual scrape action, and one notification
   for each individual channel check. Skipped checks stay quiet; playback probes
   do not notify. No native Telegram integration or offline-transition monitor.
3. Release version, documentation and issue-status reconciliation (this document).

## Upgrade notes

Back up the persistent configuration/database before upgrading. Startup uses
Alembic and creates the existing pre-upgrade SQLite backup before changing an
older revision. This cycle includes revision `20260928_1200` for channel ID kind;
it must not be described as a migration-free release.

The six deprecated environment aliases remain supported, including `.env`,
with canonical nonempty values taking precedence and name-only warnings.
Removal (#155) is deferred; this release does not retire the aliases.

Notifications remain opt-in. Webhook URLs may contain secrets in the path,
query or credentials; API reads are masked. Local/private destinations follow
the existing source-fetch policy. Test delivery before relying on notifications.

The engine is optional and a configured dedicated checker never falls back to
the playback engine on failure. ARMv7 bundled-engine runtime remains experimental
pending actual hardware validation. WARP is opt-in.
