# v2.2.0

HTTP playback, W3U catalogues, sporting events and Telegram sources, with easier guide setup and more reliable playback.

## Added

- Collect AceStream links from selected Telegram groups/channels through an optional user-account connection. Preview extraction, filter senders/topics, and recover progress after restart. Requires HTTPS or localhost, a separate admin token and encrypted session storage with an independent key. Playlist discovery and event/VOD interpretation remain separate.
- Preview and import Wiseplay/W3U catalogues, browse folders and source details, and keep selected live streams refreshed. Live-channel imports require explicit review; event broadcasts can enter the shared Events preview. Unsupported websites and VOD remain visible with their limits.
- Browse sporting events, review manual/JSON schedules or structured sports guides, follow events and choose compatible broadcasts. Map broadcasters explicitly, load optional artwork, refresh reviewed schedule URLs and configure separate event retention. Schedules stay separate from permanent TV channels; W3U entries support reviewed event imports; automatic W3U schedule extraction and Telegram event interpretation remain separate work.
- Import HTTP and HLS playlist streams, including playback headers. Add official live channels from Atresmedia, Mediaset, Telemadrid and 7 TV La Rioja by adding their websites as sources.
- Discover XMLTV guides from playlists, preview guide matches before applying them, and optionally automate unambiguous matches.
- Send optional webhook or Gotify notifications when scrapes and channel checks finish.
- Sync the bundled playback engine’s P2P port with a shared Gluetun forwarded-port file. Port changes restart playback; the dedicated checker keeps its own port.
- Read version history offline and receive a notice when a newer stable release is published. Updates remain manual: pull the new Docker image and recreate the container, or update your native installation yourself.

## Improved

- Configure tuner startup budgets for slow sources. Direct-engine startup now respects the remaining player or tuner budget, including time spent waiting for an engine slot.
- Resume overdue scheduled work after startup, prioritize older and unchecked streams fairly, and pause catalogue checks during app-owned playback.
- Preserve imported catalogues on assignment conflicts, search by stream ID, and import ZeroNet links while keeping custom gateway prefixes.
- Keep selected hosts outside WARP with explicit host exclusions. Unknown public-client routing still needs separate configuration.

## Fixed

- Resolve AceStream Search results to content IDs before adding or playing them, fixing streams that passed Check broadcast but failed with “failed to load content”. If previously added results still fail, add them again from Search and reassign TV channels to the corrected entries.

- Play imported HTTP/HLS and broadcaster streams in the browser without an AceStream engine, including freshly resolved Atresmedia links. Select audio and text subtitle tracks in the player.
- Play assigned HTTP/HLS and broadcaster sources through the Plex/Jellyfin tuner, including channels with no AceStream source. Verify HTTP media independently of the engine, refresh broadcaster links on opening, and try compatible HTTP or AceStream alternatives when startup fails. HTTP input is repackaged as MPEG-TS without re-encoding.
- Stop browser playback cleanly after terminal HTTP failures and provide bounded, masked source diagnostics. Audio and subtitle selections remain independent between viewers; subtitles default to Off.
- Respect the configured application port in containers, update bundled Kubo to 0.43.1, and report optional service states more accurately.
- Improve session cleanup, disconnect handling and HLS segment handling during playback.

## Before upgrading

- Back up persistent configuration and the database. Startup applies schema migrations using the existing backup and recovery process, including channel ID kind (20260928_1200) and HTTP stream URL/headers (20261021_1200), W3U catalogues (20261022_1200), sporting events and maintenance (20261023_1200 / 20261023_1300), their combined migration revision (20261023_1400), and Telegram source progress (20261023_1500).
- Preserve Telegram session storage and its independent encryption key when moving an installation; ordinary database/configuration backups do not include account sessions or keys.
- HTTP tuner playback requires FFmpeg, included in the container images. Native installations must provide the documented FFmpeg capabilities. Source codec compatibility still depends on the media server/client; switching sources after playback starts normally requires the client to reconnect.
- Legacy environment aliases remain supported. ARMv7 engine runtime remains experimental. Full Wiseplay compatibility, broader website resolvers, automatic Telegram/W3U event interpretation and movies/series navigation remain follow-up work.
