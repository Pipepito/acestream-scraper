# UX audit and remediation — 8 September 2026

Base: `develop` at `7a54739`, pulled with `git pull --ff-only origin develop`.
Scope: the whole web interface, with implementation focused on Live TV and management/settings navigation. Findings describe the observed build, not permanent CI or release status.

## Verdict

The product has a useful operational foundation: clear inventory boundaries, explicit stream verification states, good destructive-action confirmations, and real empty/error states. Its biggest weakness was workflow organization. Watching blocked browsing; Settings combined unrelated jobs; some management tools were difficult to discover.

**Visual anti-pattern verdict: partial fail.** Nested outlined surfaces and repeated service cards make the app feel more like a generic administration template than necessary. This is not a gradient-heavy marketing UI: its typography, operational copy and explicit status labels already give it a coherent identity. Keep the existing theme; reduce redundant containers in a later polish pass.

The audit identifies **12 findings: 0 P0, 3 P1, 8 P2, 1 P3**. Seven are addressed, one is partly addressed, and four remain as specific follow-up work. None of these scores is a WCAG certification.

## Prioritized findings

### F01 · P1 · Watching prevents channel browsing — addressed

- Location: `frontend/src/pages/LiveTV.tsx` and `components/player/StreamPlayerDialog.tsx`.
- Category: Interaction / responsive behavior.
- Impact: changing channels required closing the player and losing viewing context.
- Remediation: Live TV embeds the existing player. Desktop places the catalogue beside it; smaller screens stack independently scrollable viewing and browsing areas within a viewport. Search/favorites do not release the session. Channel switches and Stop watching retain existing cleanup paths. Playback options and the schedule are disclosed on demand. Other management pages keep their player dialogs.
- Verification: channel/stream/audio switching, filtering without release, explicit stop, browser Back, direct links, and video/search visibility across four browser sizes.
- Suggested skill for future refinement: `/adapt`.

### F02 · P1 · Settings mixes unrelated concerns — addressed

- Location: `frontend/src/pages/Settings.tsx:363`.
- Category: Information architecture.
- Impact: users must scan engine routing, addresses, playlist formats, schedules and credentials to find one setting; PID/AppID under Automation gives them the wrong meaning.
- Remediation: four tabs with persistent URL state. Playback owns engine/routing; Automation owns schedules; Stream links owns formats/PID/AppID; API access owns the browser token. Public address editing remains only in Integrations. Hidden panels preserve in-page edits across tab changes.
- Suggested skill: `/arrange`.

### F03 · P1 · Search category has no programmatic label — addressed

- Location: `frontend/src/pages/Search.tsx:188`.
- Category: Accessibility; WCAG 1.3.1 / 4.1.2.
- Impact: the visual label did not name the combobox in the accessibility tree.
- Remediation: explicit InputLabel ID and Select labelId. Category is now named for assistive technologies.
- Suggested skill: `/harden`.

### F04 · P2 · WARP discovery depends on another screen — addressed

- Location: `frontend/src/components/layout/navItems.tsx` and `components/NavBar.tsx`.
- Category: Navigation.
- Impact: users cannot reliably find the network management page from primary navigation.
- Remediation: explicit WARP entry under System; Watch and Manage separate viewing from inventory work. No service permission or connection behavior changed.
- Suggested skill: `/arrange`.

### F05 · P2 · EPG claims a fixed hourly schedule — addressed

- Location: `frontend/src/pages/EPG.tsx:226`; Overview/Scraper schedule links.
- Category: Copy / consistency.
- Impact: the description can contradict the configured refresh interval.
- Remediation: describe the configured schedule and link directly to Automation. Overview jobs and Scraper sources also link to it. Playlist opens Stream links directly.
- Suggested skill: `/clarify`.

### F06 · P2 · Keyboard users must traverse navigation repeatedly — addressed

- Location: `frontend/src/components/layout/AppShell.tsx`.
- Category: Accessibility; related to WCAG 2.4.1.
- Impact: a large sidebar adds repeated tab stops before page controls.
- Remediation: focus-visible Skip to content link and focusable main target. Existing navigation labels and active-page state remain.
- Suggested skill: `/harden`.

### F07 · P2 · Unrelated settings requests block access — addressed

- Location: `frontend/src/pages/Settings.tsx:507` and Automation fields.
- Category: Resilience.
- Impact: browser token entry previously waited for unrelated settings; failed schedule reads could leave apparent defaults editable.
- Remediation: loading depends on the selected concern; API access does not wait for other reads. Failed scrape/EPG interval reads show an error and disable their saves, matching the existing channel-check behavior.
- Suggested skill: `/harden`.

### F08 · P2 · Guide inventory lacks channel search — open

- Location: `frontend/src/pages/EPG.tsx:250`, guide-channel inventory.
- Category: Management efficiency.
- Impact: finding a known channel among 636 entries requires source filtering and page scanning.
- Recommendation: add server-side name/XML-ID search plus Linked/Unlinked filtering, preserve filters in the URL, and reset pagination when filters change. Do not filter only the current 50 rows and imply it searched the whole guide. Verify selection behavior across filtered pages and the create-TV-channel action.
- Suggested skill: `/harden`, then `/arrange`.

### F09 · P2 · Source-mode service cards repeat/conflict — open

- Location: `frontend/src/components/ServicesPanel.tsx:63` and `:215`.
- Category: State clarity.
- Impact: the banner says services are external, while cards repeatedly say Not installed / Not included in this image flavor. Operators can misread a local source run as a broken image.
- Recommendation: distinguish External/unreachable from image capability, and show one availability explanation per service. Keep version, endpoint and restart constraints under a concise details disclosure. Align this with backend service metadata rather than guessing from reachability.
- Suggested skill: `/clarify` and `/distill`.

### F10 · P2 · Network errors expose implementation detail — partly addressed

- Location: Settings engine status; `frontend/src/pages/Scraper.tsx:80`.
- Category: Recovery / copy.
- Impact: errno, SSL connection tuples and retry internals do not tell a nontechnical operator what to do.
- Remediation completed: unreachable-engine guidance now asks users to check the address and running service.
- Remaining recommendation: map scraper failures to short cause/action pairs, such as “IPFS gateway unavailable — check the gateway service and retry.” Keep bounded technical detail available for diagnostics, not as the only accessible error label.
- Suggested skill: `/clarify`.

### F11 · P2 · Heavy startup bundles and full catalogue fetch — open

- Location: `frontend/src/App.tsx`, `frontend/src/services/tvChannelService.ts:107`, Vite output.
- Category: Performance.
- Impact: slower devices download/parse code for management and playback features they may not use; a large TV catalogue is fetched sequentially in full.
- Evidence: build reports approximately 575 kB player and 676 kB data-grid chunks before gzip. These are bundle observations, not measured Core Web Vitals failures.
- Recommendation: profile cold-load timing, then lazy-load route/player boundaries while preserving the established manual chunk contract. Add a purpose-built paged viewing API if large catalogues justify it; keep the selected player independent of catalogue pagination.
- Suggested skill: `/optimize`.

### F12 · P3 · Repeated containers dilute hierarchy — open

- Location: `components/layout/AppShell.tsx`, ContentSection and Overview service cards.
- Category: Visual anti-patterns.
- Impact: outlines within outlines make the interface denser without adding meaning.
- Recommendation: flatten one surface level in management pages, keep borders for actual grouping, and preserve the current typography/theme tokens. Avoid a whole-brand redesign for this issue.
- Suggested skill: `/distill`, then `/polish`.
